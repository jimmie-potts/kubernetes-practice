# Labs teach by predicting, drilling, fading, and teaching back

Each lab asks the reader to predict a command's output before running it, ends with a drill that injects a random fault for the reader to diagnose (`scripts/drills/phase-N.sh break|check|undo`), hides the commands of one repeated task behind a hint so the reader tries it unaided, and closes with teach-back prompts whose answers the reader exports for review. A sourced shell script, `scripts/lab-journal.sh`, records the commands typed during a lab to the gitignored `.journal/` folder so the review can see retries and errors. Steps cite official documentation. Chosen because the labs already had guided steps, expected outputs, ECS mappings, and recognition quizzes, but nothing that made the reader retrieve, diagnose, or explain, and those are the activities that transfer to on-call work and interviews. Drills pick a fault at random so a repeat run stays a diagnosis rather than a recital. Hints are staged and keyed by symptom so a stuck reader gets the method (where to look, what to run) before the answer. The fade tightens with each phase: one hidden-command step in phases 0 to 2, two in phases 3 and 4, and from phase 5 on a repeated task links to the earlier lab instead of showing commands.

## Consequences

The template contract in `docs/labs/assets/TEMPLATE.html` gains rules 11 to 17. Drill scripts take their cluster from `FORGE_CONTEXT` so the validation cluster can exercise every fault. A phase is not done until the teach-back answers and the journal have been reviewed; `docs/agents/labs.md` holds the routine. Deferred until phase 3 exists: a concept ledger on the dashboard and a cross-phase retrieval warm-up.
